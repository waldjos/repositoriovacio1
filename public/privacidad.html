PRIVACIDAD Y DATOS

Política de Privacidad

Explica qué información utiliza ZiviFactura y cómo se protege al operar cuentas, negocios, documentos compartidos, pagos y respaldos.

1. Responsable y alcance

ZiviFactura es un servicio desarrollado por Zivi Dynamics C.A. Esta política aplica a la aplicación web, su PWA y las funciones de autenticación, sincronización, enlaces de documentos, recepción de comprobantes y respaldo.

2. Información que puede tratar la aplicación

Según las funciones utilizadas, ZiviFactura puede tratar:

  • Datos de cuenta como nombre y correo. Las contraseñas son gestionadas por Firebase Authentication y ZiviFactura no conserva una copia legible.
  • Datos básicos de Google Sign-In cuando el usuario elige ese método de autenticación.
  • Datos de uno o varios negocios configurados bajo una misma cuenta, incluyendo nombre, RIF/RUC, teléfonos, correo, dirección, moneda, numeración, impuestos y métodos de cobro.
  • Datos de clientes, facturas, presupuestos, proformas, productos, importes, cuentas por cobrar, cobros, abonos, referencias y observaciones.
  • Datos de pago configurados por cada negocio, como pago móvil, cuenta bancaria, Binance Pay u otras instrucciones.
  • Cuando se habilita un enlace de documento, una copia de la información necesaria para que el destinatario pueda consultar ese documento y los métodos de pago disponibles.
  • Cuando un pagador envía un comprobante, monto reportado, moneda, método, fecha, referencia, comentario y una imagen comprimida del voucher.
  • Información técnica mínima para mantener la sesión, sincronizar y conservar información local.

3. Finalidades

La información se utiliza para autenticar cuentas, administrar uno o varios negocios, emitir y compartir documentos, registrar cobros y cuentas por cobrar, recibir comprobantes, generar PDF y recibos, producir estadísticas, sincronizar entre dispositivos y habilitar respaldos.

4. Inicio de sesión y Firebase

ZiviFactura utiliza Firebase Authentication y Cloud Firestore. Los datos sincronizados se organizan bajo el identificador de la cuenta. Los comprobantes optimizados pueden almacenarse dentro de su registro en Firestore y las reglas de acceso buscan limitar su lectura al emisor autenticado correspondiente.

Al usar Google Sign-In, ZiviFactura no solicita acceso a Gmail, Google Drive, contactos ni calendario. La integración se utiliza únicamente para autenticación básica.

5. Enlaces públicos de documentos

El emisor puede generar un enlace para que un destinatario consulte una factura, presupuesto o proforma, vea los datos de pago habilitados, cargue un comprobante y descargue una copia del documento. El enlace utiliza un identificador difícil de adivinar, pero quien tenga acceso al enlace podrá visualizar la información publicada en él. Por ello, el emisor y el destinatario deben tratarlo como información privada y evitar compartirlo con terceros no autorizados.

6. Comprobantes enviados por pagadores

El pagador puede cargar un voucher sin crear una cuenta tradicional. Para el envío se utiliza una sesión técnica temporal de Firebase Authentication. La imagen se comprime antes de enviarse y queda pendiente de revisión. Subir un comprobante no confirma automáticamente el pago ni modifica por sí solo el estado contable; el emisor debe validarlo y registrar el cobro.

7. Almacenamiento local y nube

ZiviFactura utiliza un enfoque local-first mediante IndexedDB y almacenamiento local del navegador. Cuando el usuario inicia sesión y existe conexión, la aplicación puede sincronizar información con Cloud Firestore. Los enlaces públicos y comprobantes enviados también pueden conservarse en Firestore mientras resulten necesarios para prestar la función.

8. Proveedores tecnológicos

Para prestar el servicio pueden intervenir Google/Firebase para autenticación y base de datos, Vercel para alojamiento y ejecución y, cuando esté habilitado, un proveedor de correo transaccional para respaldos.

9. Analítica, publicidad y venta de datos

La versión actual de ZiviFactura no activa Google Analytics, publicidad comportamental ni remarketing dentro de la aplicación. Zivi Dynamics C.A. no vende los datos personales almacenados en ZiviFactura.

10. Conservación y eliminación

Los datos se conservan mientras sean necesarios para prestar el servicio o hasta que el usuario los elimine o solicite su eliminación. La eliminación local no necesariamente elimina una copia previamente sincronizada en Firestore. Los enlaces y comprobantes podrán conservarse mientras sean necesarios para documentar la operación relacionada.

11. Seguridad

Se aplican controles técnicos razonables como autenticación, reglas de acceso, identificadores de enlace no secuenciales, límites de tamaño para comprobantes, conexiones HTTPS y mecanismos de seguridad de Firebase y Vercel. Ningún sistema garantiza riesgo cero.

12. Derechos y contacto

El usuario puede solicitar información, corrección o eliminación de datos asociados a su cuenta escribiendo a ziviagency@gmail.com. La solicitud podrá requerir verificación razonable de identidad.

13. Cambios de esta política

Esta política podrá actualizarse cuando cambien las funciones, proveedores o requisitos aplicables.
