PRIVACIDAD Y DATOS

Política de Privacidad

Explica qué información utiliza ZiviFactura, para qué se usa y cómo se protege al operar la aplicación y sus funciones de autenticación, sincronización, recepción de comprobantes y respaldo.

1. Responsable y alcance

ZiviFactura es un servicio desarrollado por Zivi Dynamics C.A. Esta política aplica al uso de la aplicación web, su versión instalable PWA y los servicios de autenticación, sincronización, recepción de comprobantes de pago y respaldo asociados.

2. Información que puede tratar la aplicación

Según las funciones que utilices, ZiviFactura puede tratar:

  • Datos de cuenta proporcionados al registrarse, como nombre, correo electrónico y datos básicos necesarios para identificar al usuario. La contraseña es gestionada por Firebase Authentication y ZiviFactura no almacena una copia legible de ella.
  • Cuando se utiliza Google Sign-In, datos básicos de la cuenta de Google empleados para identificar al usuario, como identificador de Firebase, nombre, correo electrónico y foto de perfil cuando estén disponibles.
  • Datos de empresa que el usuario configure o proporcione durante el registro, como razón social, RIF/RUC, teléfonos, correo, dirección, ciudad, moneda, numeración, impuestos y métodos de cobro.
  • Datos de clientes ingresados por el usuario, como nombre, documento fiscal, teléfono, correo y dirección.
  • Facturas, presupuestos, proformas, productos, servicios, importes, impuestos, cuentas por cobrar, cobros, abonos, estados de pago, referencias y observaciones creados dentro de la aplicación.
  • Datos de pago que el propio usuario decida incorporar, por ejemplo pago móvil, cuenta bancaria, Binance Pay u otras instrucciones de cobro.
  • Cuando una factura habilita la recepción de comprobantes, el pagador puede enviar voluntariamente el monto reportado, moneda, método de pago, fecha, referencia, comentario y un archivo de comprobante o voucher en formato de imagen o PDF. Este material queda asociado a la cuenta del emisor de la factura para su revisión.
  • Información técnica mínima necesaria para mantener la sesión, sincronizar y conservar los datos de forma local.

3. Finalidades

Los datos se utilizan para crear y autenticar cuentas, identificar al usuario, configurar su empresa, crear y administrar documentos, registrar cobros y cuentas por cobrar, recibir y revisar comprobantes de pago, generar PDF y recibos, conservar historial, producir estadísticas administrativas, sincronizar información entre dispositivos, restaurar información y habilitar respaldos cuando esa función esté configurada.

4. Inicio de sesión y Firebase

ZiviFactura utiliza Firebase Authentication para el registro e inicio de sesión mediante correo y contraseña y, cuando el usuario lo elige, mediante Google Sign-In. Cloud Firestore se utiliza para sincronización y para asociar comprobantes enviados a la cuenta correcta. Firebase Storage puede utilizarse para almacenar los archivos de vouchers o comprobantes. Los datos de cada cuenta se organizan bajo su identificador de usuario y las reglas de acceso están diseñadas para limitar la lectura de esos comprobantes al emisor autenticado correspondiente.

Al usar Google Sign-In, ZiviFactura no solicita acceso a Gmail, Google Drive, contactos ni calendario. El acceso se utiliza únicamente para autenticación básica. ZiviFactura tampoco recibe la contraseña de la cuenta de Google.

5. Comprobantes enviados por pagadores

La página pública incluida en determinadas facturas permite que un pagador cargue un voucher sin crear una cuenta tradicional en ZiviFactura. Para realizar ese envío se utiliza una sesión técnica temporal de Firebase Authentication y el comprobante queda pendiente de revisión. Cargar un archivo no confirma automáticamente que el pago sea válido ni modifica por sí solo el estado contable de la factura; el emisor debe revisarlo y registrar el cobro.

6. Almacenamiento local y nube

La aplicación funciona con un enfoque local-first. Parte de la información se conserva en el dispositivo mediante IndexedDB y almacenamiento local del navegador. Cuando el usuario inicia sesión y existe conexión, la aplicación puede sincronizar la información con Cloud Firestore. Los comprobantes de pago enviados mediante la página pública pueden almacenarse en Firebase Storage.

7. Proveedores tecnológicos

Para prestar el servicio pueden intervenir proveedores tecnológicos como Google/Firebase para autenticación, base de datos y almacenamiento de comprobantes, Vercel para alojamiento y ejecución de la aplicación y, cuando el respaldo por correo esté habilitado, un proveedor de correo transaccional. Estos servicios pueden tratar datos técnicos y operativos necesarios para prestar sus funciones conforme a sus propias políticas y condiciones.

8. Analítica, publicidad y venta de datos

La versión actual de ZiviFactura no activa Google Analytics, publicidad comportamental ni herramientas de remarketing dentro de la aplicación. Zivi Dynamics C.A. no vende los datos personales almacenados en ZiviFactura.

9. Conservación y eliminación

Los datos se conservan mientras sean necesarios para prestar el servicio o hasta que el usuario los elimine, restaure un respaldo que los reemplace, cambie de cuenta o solicite la eliminación de los datos asociados a su cuenta. Los comprobantes de pago podrán conservarse mientras resulten necesarios para documentar o verificar el movimiento relacionado. La eliminación local del navegador no necesariamente elimina una copia ya sincronizada en Firestore o almacenada en Firebase Storage.

10. Seguridad

Se aplican controles técnicos razonables, incluyendo autenticación, reglas de acceso por usuario, límites de tipo y tamaño para archivos de comprobantes, conexiones HTTPS y los mecanismos de seguridad proporcionados por Firebase y Vercel. Ningún sistema puede garantizar riesgo cero, por lo que se recomienda utilizar una contraseña única, proteger la cuenta utilizada para acceder y mantener respaldos cuando corresponda.

11. Derechos y contacto

El usuario puede solicitar información, corrección o eliminación de datos asociados a su cuenta escribiendo a ziviagency@gmail.com. La solicitud podrá requerir verificación razonable de identidad antes de ejecutarse.

12. Cambios de esta política

Esta política podrá actualizarse cuando cambien las funciones de ZiviFactura, sus proveedores o los requisitos aplicables. La fecha de actualización se indicará en esta página.
